## 2026-09-14. Добавление Lakekeeper

**Сделано**

- Создал БД для Lakekeeper (postgreSQL)
- Сделал 2 контейнера для Lakekeeper (сам lakekeeper и migrate). Lakekeeper будет отвечать за метаданные о текущем состоянии таблиц и допускать изменение только одним писателем. 
    Migrate создает необходимые каталоги и таблицы внутри БД PostgreSQL, с которыми будет работать Lakekeeper.
- Добавили init-container для создания warehouse в lakekeeper. Json конфигурация передается с помощью -X POST в lakekeeper. Чтобы обеспечить идемпотентность в создании warehouse 
    попросил claude сделать скрипт перемещения с условием, что такой warehouse ещё не существует.

**Решения**

- Для метаданных выьрали Lakekeeper (возможно стоило hive metastore, но думаю, что позже немного его сделаем)
- Для хранения метаданных выьрали PostgreSQL

**Грабли**

- Список аргументов в exec-форме -> падающий Healthcheck. Причина: ["CMD", "pg_isready --username=admin"], команда и флаг склеены в один элемент. Вывод: в списках каждый аргумент отдельным элементом, первый это программа.
- Том монтируется туда, куда программа реально пишет. Симптом: том есть, а данные после пересоздания пропадают. Причина: смонтировал в /data_pg, а постгрес пишет в /var/lib/postgresql/data. Вывод: точка монтирования диктуется программой, а не тобой.
- Подстановка захватывает весь вывод команды. Симптом: warehouse создался с кодом 201, а скрипт написал failed. Причина: убрал -o /dev/null, тело ответа слиплось с кодом в переменной. Вывод: в переменную должно попадать ровно то, что ты сравниваешь, остальное в файл или в другой поток.

**Дальше**

- Установка Trino.

## 2026-09-13. MinIO и автосоздание бакета

**Сделано**

- Поднял MinIO в docker compose: постоянный том, healthcheck, консоль на 9223, S3 API на 9222.
- Добавил одноразовый init-контейнер с `mc`: дожидается healthy, заводит алиас и создает бакет `minilakehouse` идемпотентно.
- Проверка: `docker compose down -v && docker compose up -d` поднимает стенд с нуля, бакет появляется сам.

**Решения**

- Каталогом берем Lakekeeper (Iceberg REST catalog), а не Hive Metastore: меньше контейнеров, есть UI, ближе к текущей практике.
- Бакет создается init-контейнером, а не руками в UI: стенд должен подниматься одной командой без ручных шагов.

**Грабли**

- Бакет не создавался, хотя в compose стояла переменная `MINIO_DEFAULT_BUCKETS`. Причина: эту переменную читает образ от bitnami, официальный ее не знает и молча игнорирует. Вывод: переменные окружения это контракт конкретного образа, проверять в его документации.
- `pull access denied for minio/minio`. Причина: MinIO убрал образы с Docker Hub, community-редакция заархивирована, развивается только коммерческий AIStor. Вывод: брать `quay.io/minio/minio` с явным тегом; образ без префикса реестра докер всегда ищет на Docker Hub.
- Init-контейнер завершался с кодом 0 и печатал переменные окружения вместо работы. Причина: `command` строкой compose режет на слова, и до `sh -c` дошла только первая команда `set`, остальное ушло в позиционные аргументы. Вывод: скрипт передавать одним элементом списка через блочный скаляр. Код возврата 0 не означает, что работа сделана.
- `mc: <ERROR> ... Invalid Request (invalid hostname)`. Причина: адрес указывал на `localhost`, то есть на сам init-контейнер, а после исправления на имя сервиса вылезло подчеркивание в `minio_tblrka`, которое клиент на Go отвергает как невалидное имя хоста. Вывод: имена сервисов в compose писать строчными через дефис, они живут в DNS. Адрес всегда определять по вопросу, какой процесс в каком контейнере выполняет команду.

**Дальше**

- Lakekeeper: своя база Postgres под метаданные, одноразовый контейнер с командой `migrate`, затем сервер.
